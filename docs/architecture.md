# Architecture and data flow

```text
CLI/files ──> Rust parser (Pest bridge) ──> AST ──> JSON/CBOR/CSV validators
                                      └───────> Rust code generator

VS Code client <── LSP over IPC/stdio ──> TypeScript language server
                                         └──> Node WASM parser (lsp feature)

Browser editor ──> web WASM parser/validators (default features)
       ├──> outline, completions and bounded sample generator
       ├──> localStorage preferences/documents
       └──> explicit share link encoded entirely in the URL fragment
```

The library owns parsing, AST and validation semantics. Rustdoc generated by
`cargo doc --all --no-deps` is the API reference; generated WASM `.d.ts` files
describe the JavaScript boundary. The language server implements the standard
Language Server Protocol, with capabilities returned by `initialize`; its
stdio integration tests check diagnostics, completions and symbols.

Map key type choices match each key independently: `{ * (int / tstr) => any }`
accepts mixed integer and text keys in CBOR. Named choices and constraints on
their alternatives are also checked. Occurrence bounds count matching key/value
pairs across all alternatives, not separately for each alternative.

The client never imports server internals. Browser modules never import LSP
sources. ESLint enforces these source boundaries; the generated WASM packages
are the shared implementation, not hand-maintained JavaScript copies.

The playground is a static application. It has no backend, database, account
system or server-side secrets. Validation stays on the user's machine.
`share.js` validates incoming fragments and bounds decoded state; `sample-gen.js`
bounds tokens, depth, repetitions and nodes and marks best-effort output as
unverified until the Rust validator accepts it. Import/export uses local files.

`www/webpack.config.js` provides the common build configuration. Production
adds hashed assets and measured size budgets. Only the editor and JSON language
support are bundled; there is no reason to ship TypeScript/CSS/HTML workers.
The extension's webpacks are separate from the static playground.

Database schema management, N+1 queries, distributed tracing, circuit breakers
and backend service health endpoints do not apply to this architecture. Do not
add dummy services or telemetry to satisfy a generic readiness checklist.
